## How to reproduce this from a fresh clone

These steps assume a fresh `git clone` of this repository with nothing else installed.

1. **Clone the repository:**
   ```
   git clone https://github.com/Sagardeakin/Heart-desease-project.git
   cd Heart-desease-project
   ```

2. **(Recommended) create a virtual environment:**
   ```
   python3 -m venv venv
   source venv/bin/activate      # on Windows: venv\Scripts\activate
   ```

3. **Install dependencies from `requirements.txt`:**
   ```
   pip install -r requirements.txt
   ```

4. **Confirm `heart.csv` is present** in the same folder as the scripts/notebook (it is included in this
   repository, so no extra download step is needed).

5. **Run the reproduction and proposed-solution scripts directly:**
   ```
   python3 part1_reproduction.py
   python3 part2_improved.py
   ```
   Each script prints per-model metrics to the terminal and regenerates the `fig_*.png` figures and
   `*_results.csv` / `*_summary.json` files in the same folder.

   **Or**, open and run the notebook top-to-bottom:
   ```
   jupyter notebook SIT720_11.1HD-2.ipynb
   ```
   or execute it non-interactively:
   ```
   jupyter execute --inplace SIT720_11.1HD-2.ipynb
   ```

6. All figures (`fig_part1_*.png`, `fig_part2_*.png`, `fig_comparison_all.png`) and result files
   (`part1_all_results.csv`, `part2_all_results.csv`, `part2_best_params.json`, etc.) are regenerated
   in the same folder after running the scripts or notebook.

## Key finding

The Kaggle "1025-row" heart-disease dataset contains 723 exact duplicate rows
(only 302 unique patients). A random train/test split — as used in the original
paper — leaks duplicated patients across train/test, letting tree-based models
(DT/RF/XGBoost) and the stacking ensemble reach up to 100% test accuracy by
memorisation rather than genuine generalisation. The proposed solution
deduplicates the data and evaluates with nested, repeated stratified
cross-validation, giving a realistic accuracy of **82.9% ± 4.2%** for a
hyperparameter-tuned stacking ensemble — still the best of all seven models
tested, but far below the paper's reported 98.53%. This finding is consistent
with the broader literature on data leakage in ML-based research (Kapoor &
Narayanan, 2023) and near-duplicate train/test contamination in other domains
(Barz & Denzler, 2020); see the full reference list in the report.
